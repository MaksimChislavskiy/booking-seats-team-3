# 🔧 Настройка окружений: локальная разработка и Docker

Проект использует два разных файла окружения, так как приложение работает в двух независимых средах:

* **локально**
* **в Docker-контейнерах**

Эти среды используют *разные адреса подключения к PostgreSQL*, поэтому требуется раздельная конфигурация.

---

## 1. Файл `.env` — локальная разработка

Используется, когда backend запускается **вне Docker**, через:

```
uvicorn app.main:app --reload
```

### Основные параметры

```
POSTGRES_SERVER=localhost
POSTGRES_PORT=5432
```

Локальное приложение подключается к PostgreSQL, который работает в Docker, через проброшенный порт `5432`.

---

## 2. Файл `.env.docker` — запуск backend внутри Docker

Используется, когда проект запускается полностью через Docker Compose.

### Основные параметры

```
POSTGRES_SERVER=db
POSTGRES_PORT=5432
```

`db` — это имя сервиса PostgreSQL в Docker Compose.
Docker создаёт внутреннюю сеть, и контейнеры видят друг друга по этим именам.

---

# 🐳 Запуск Docker

## 1. Запуск всей инфраструктуры (backend + db + nginx)

```
docker compose -f infra/docker-compose.yml up --build
```

Использует `.env.docker`.
Backend внутри контейнера подключается к PostgreSQL по адресу:

```
db:5432
```

---

## 2. Запуск только базы данных (для локальной разработки)

Для разработки удобнее поднимать только PostgreSQL:

```
docker compose -f infra/docker-compose.yml up db
```

Это запустит только сервис `db` и оставит backend за пределами Docker.

### Локальная схема работы

1. Поднимаем PostgreSQL в Docker
2. Backend запускаем локально (`uvicorn ...`)
3. Alembic создаёт миграции и применяет их к базе на `localhost:5432`

## Главное различие:

- localhost нужен локальным инструментам (Alembic, uvicorn), чтобы подключаться к контейнеру PostgreSQL через проброшенный порт.
- db нужен контейнерам внутри одного Docker Compose — это их способ “видеть” друг друга в сети.

# Шаблон для проектов со стилизатором Ruff

## Основное

1. Базовая версия Python - 3.11.
2. В файле `requirements_style.txt` находятся зависимости для стилистики.
3. В каталоге `src` находится базовая структура проекта
4. В файле `srd/requirements.txt` прописываются базовые зависимости.
5. В каталоге `infra` находятся настроечные файлы проекта. Здесь же размещать файлы для docker compose.

## Стилистика

Для стилизации кода используется пакеты `Ruff` и `Pre-commit`

Проверка стилистики кода осуществляется командой

```shell
ruff check
```

Если одновременно надо пофиксить то, что можно поиксить автоматически, то добавляем параметр `--fix`

```shell
ruff check --fix
```

Что бы стилистика автоматически проверялась и поправлялась при комитах надо добавить hook pre-commit к git

```shell
pre-commit install
```
